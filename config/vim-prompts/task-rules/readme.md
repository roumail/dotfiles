## READMEs

A README says what a user can do and rely on. It follows the same limits as
the `comments` rule:

- **Describe behaviour, not the implementation.** Say what callers can count
  on, not the steps that produce it.
- **Must stay true as the code changes.** If a sentence could drift from the
  code without a user noticing, cut it.
- Build only what is asked: no section for a case nobody has today.
